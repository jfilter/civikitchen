# Configuration

Two prefixes, by ownership: `CIVIKITCHEN_*` vars are this project's own behavior knobs; `CIVICRM_*` is reserved for the CiviCRM-side contract (`CIVICRM_AUTO_INSTALL`, and `CIVICRM_DB_*` — core composes its DSN from these at boot), for describing the CiviCRM/civibuild target (`CIVICRM_VERSION`, `CIVICRM_SITE_TYPE`) and for CiviCRM's own variables (e.g. `CIVICRM_UF`). Legacy `CIVICRM_`-spelled kitchen vars (and `SITE_URL`) keep working with a deprecation warning. Where a var only makes sense for one image family, the **Image** column flags it.

| Env var | Default | Image | Purpose |
|---------|---------|-------|---------|
| `CIVICRM_DB_HOST` | `db` | all | DB hostname. |
| `CIVICRM_DB_PORT` | `3306` | all | DB port. |
| `CIVIKITCHEN_SITE_URL` | derived | all | Browser-facing URL Civi bakes into asset paths; must match the host:port the user opens, or assets 404. On the demo images it rewrites the baked base URL at boot ([Demo images](images.md#demo-images)). |
| `CIVICRM_AUTO_INSTALL` | `0` | standalone | Set to `1` to auto-install CiviCRM on first start (when `civicrm.settings.php` is missing). |
| `CIVICRM_DB_NAME` | `civicrm` | standalone | Database name (the standalone image connects with the app user; buildkit creates DB + user itself). |
| `CIVICRM_DB_USER` | `civicrm` | standalone | DB user used by the running CiviCRM. |
| `CIVICRM_DB_PASSWORD` | `civicrm` | standalone | Password for `CIVICRM_DB_USER`. |
| `CIVIKITCHEN_DEMO_USER` | _(unset)_ | standalone | If set during auto-install, creates a CiviCRM login user with this username and the `admin` role. Requires `CIVICRM_AUTO_INSTALL=1`. |
| `CIVIKITCHEN_DEMO_PASS` | `admin` | standalone | Password for the demo user. |
| `CIVIKITCHEN_DEMO_EMAIL` | `admin@example.org` | standalone | Email for the demo user's contact record. |
| `CIVIKITCHEN_COMPONENTS` | all standard | standalone | Comma-separated CiviCRM components to enable at install. Defaults to the full set: `CiviEvent,CiviContribute,CiviMember,CiviMail,CiviPledge,CiviCase,CiviReport,CiviCampaign`. Override to narrow the set, or pass an empty string for `cv`'s own core-only default. |
| `CIVIKITCHEN_SMTP_HOST` | _(unset)_ | all | If set, points Civi's `mailing_backend` at this SMTP host after install. The example compose stack uses `maildev` so outbound mail lands in the maildev UI on `:1080`. On the buildkit flavors this also removes buildkit's `app/civicrm.settings.d/100-mail.php`, which cannot see the DB-level backend and would otherwise define `CIVICRM_MAIL_LOG=/dev/null` — silently swallowing all outbound mail. |
| `CIVIKITCHEN_SMTP_PORT` | `1025` | all | Port for `CIVIKITCHEN_SMTP_HOST`. |
| `CIVIKITCHEN_EXTRA_EXTENSIONS` | _(unset)_ | all | Comma-separated extension keys downloaded + enabled after install — e.g. `de.systopia.xcm,de.systopia.twingle`. A bare key whose version-constrained, digest-pinned source is declared under `policy.extension_sources` in a mounted extension's `civikitchen.yaml` is downloaded from that verified source. Explicit `key@URL` values remain an operator override and are not called pinned. Runs once during first-boot provisioning. |
| `CIVIKITCHEN_ENABLE_EXTENSIONS` | _(unset)_ | all | Every extension **bind-mounted** into `/var/www/html/ext` is enabled after install without being named here. This variable is the ordering override. Each extension's `info.xml` `<requires>` is resolved first: a missing dependency comes from the registry or from its Composer-version-constrained HTTPS + SHA-256 `policy.extension_sources` entry, then is enabled before the extension. |
| `CK_DEP_ARCHIVE_DIR` | _(unset)_ | all | Directory of dependency release archives staged from outside the container, read when a `policy.extension_sources` entry pins a dependency to a `release:` instead of a `url:`; the entrypoint verifies each against the pinned SHA-256. A release pin whose archive is not here is an error, never a fall back to the registry. See [A dependency only a credential can reach](extension-releases.md#a-dependency-only-a-credential-can-reach). |
| `CIVIKITCHEN_LOCALES` | _(unset)_ | all | Comma-separated CiviCRM locales (e.g. `de_DE,fr_FR`) whose **core** language files are installed at first boot: the version-matching `civicrm-<version>-l10n.tar.gz` is streamed from download.civicrm.org and only the requested locales are unpacked into `[civicrm.l10n]`. Without them core strings stay English, while an extension's own `l10n/<locale>/LC_MESSAGES/<file>.mo` still translates (measured on 6.16 and 6.18), so testing an extension's catalogue needs no core language files. Off by default: the tarball is ~100 MB and most stacks stay `en_US`. An unknown locale fails the boot instead of leaving English behind. |
| `CIVIKITCHEN_DEFAULT_LOCALE` | _(unset)_ | all | The site's language. Must be one of `CIVIKITCHEN_LOCALES` — a default without its language files is an error, not a silent English fallback. On standalone the site is **installed** in it: the language files are fetched before `cv core:install --lang=<locale>`, so the seed data labels (financial types, membership statuses, location types, payment instruments, …) are translated while their machine names stay English, and the installer applies core's defaults for the locale from `settings/l10n/<locale>/settings.default.json` (for `de_DE`: EUR, Germany, ISO dates, Europe/Berlin). It only acts at install time — an existing site keeps its data. The buildkit flavors create their site with civibuild and only set `lcMessages` afterwards, so their seed labels stay English. |
| `CIVIKITCHEN_PROFILE` | _(unset)_ | all | One or more profiles, comma-separated, applied in order once at first boot: `verein`, `fundraising`, `events`, `mailing`, or one from `CIVIKITCHEN_PROFILE_PATH`. Needs network and takes a few minutes. See [Profiles](images.md#profiles-civikitchen_profile). |
| `CIVIKITCHEN_PROFILE_PATH` | _(unset)_ | all | Colon-separated external profile roots, each containing `<name>/profile.json`. See [Profiles](images.md#profiles-civikitchen_profile). |
| `CIVIKITCHEN_TRUST_EXTERNAL_PROFILES` | `0` | all | Required as `1` before any profile resolved outside the bundled root may run — a trust decision for the entire mounted root, including its shell drivers and PHP seeds. |
| `CK_CREDENTIALS_FILE` | web user's `$HOME/api-credentials.txt` | all | Overrides where the profile's API-user provisioning (`configure-api-users.php`) writes the generated credentials (one `username:password:api_key` line per apiUser). Defaults to `api-credentials.txt` in the web user's `$HOME` (`/home/buildkit/` on buildkit flavors, `~www-data/` on the standalone dev image). By convention, profile seeds may write sibling files next to it (e.g. a site-key export), so consumers that `docker cp` the credentials out can pick up the whole directory. |
| `CK_CREDENTIALS_OUTPUT` | `file` | all | Controls disclosure of randomly generated passwords and API keys: `file` writes only the mode-`0600` credentials file; `log` first removes any stale file and prints only to the container log; `both` does both; `none` removes any stale file and leaves the newly randomized credentials only in the configured accounts. Logging is opt-in because CI commonly archives container logs. Unknown values abort before API users are created. |
| `CIVIKITCHEN_AUTO_COMPOSER` | `1` | all | If `1`, scan `/var/www/html/ext/*/composer.json` on every container start and run `composer install` in each extension directory whose `vendor/` is missing. Removes the manual gate before `vendor/bin/phpunit` works. Idempotent (skips when `vendor/` exists), non-fatal on failure. Set to `0` if you ship `vendor/` in your repo or want full control. |
| `CIVIKITCHEN_TEST_DB` | `1` | standalone | If `1`, configure the isolated headless-test database `<db>_test` (e.g. `civicrm_test`): created, granted and seeded as the database root user on first install, `TEST_DB_DSN` and the boot-stub patch written on every boot. Set to `0` to manage `TEST_DB_DSN` yourself. See [Headless tests](extension-development.md#headless-tests). |
| `CIVIKITCHEN_EXTRA_PACKAGES` | _(unset)_ | standalone | Comma- or space-separated Debian packages installed on container start (e.g. `libreoffice-writer,unoconv` for CiviOffice rendering) — heavyweight or niche deps stay out of the image. Restarts skip packages that are already present. |
| `CIVIKITCHEN_CV_AS_ROOT` | `0` | standalone | `cv` inside the container is wrapped to always run as `www-data`, even from `docker compose exec` (root) — root-run `cv` leaves root-owned caches/locks that break the web workers. Set to `1` to bypass the wrapper and run `cv` as root. |
| `HTTPD_DOMAIN` / `HTTPD_PORT` | `localhost` / `80` | buildkit | Inputs to the *derived* default of `CIVIKITCHEN_SITE_URL` (`http://<domain>[:<port>]`). Setting `CIVIKITCHEN_SITE_URL` directly overrides both. |
| `XDEBUG_MODE` (+ `XDEBUG_CLIENT_HOST`, `XDEBUG_CLIENT_PORT`, `XDEBUG_START_WITH_REQUEST`, `XDEBUG_DISCOVER_CLIENT_HOST`, `XDEBUG_IDEKEY`) | off | all | Xdebug is installed but disabled until `XDEBUG_MODE` is set (e.g. `debug,develop`). Defaults: client `host.docker.internal:9003`, `start_with_request=trigger`, `discover_client_host=0`, idekey `VSCODE`. See [IDE step debugging](extension-development.md#ide-step-debugging). |
| `CIVICRM_DB_ROOT_PASSWORD` | `root` | all | DB **admin** password. civibuild uses it to create the per-site database and user during the first-run site build; the standalone image uses it to create, grant and seed the `<db>_test` headless-test database (`CIVIKITCHEN_TEST_DB`). |
| `CIVIKITCHEN_REINSTALL` | `0` | buildkit | Set to `1` for one boot to let a **fresh** app container rebuild over an existing civikitchen site in the external DB (sentinel in `civikitchen_state`; see [Buildkit flavors](images.md#buildkit-flavors-dev)). Without it the boot also refuses when the sentinel cannot be read at all (root access denied, connection lost) rather than treating that as "no site". |
| `CIVICRM_SITE_TYPE` | tag default | buildkit | civibuild site type. Defaults: `:drupal10` = `drupal10-demo`, `:drupal11` = `drupal11-demo`, `:wordpress` = `wp-demo`, `:joomla` = `joomla-demo`. Override to use any [civibuild template](https://docs.civicrm.org/dev/en/latest/tools/civibuild/) (`drupal11-demo` itself is not an upstream template — CiviKitchen vendors it, see [`docker/buildkit/site-types/drupal11-demo/`](../docker/buildkit/site-types/drupal11-demo/)). |
